Learn Testing Data & ML Code with Phoebe

What test would fail if the code were wrong: unit tests for transforms, data checks and model behaviour. Find the cheapest set of tests that catches the bugs data and ML code actually ship. Data code fails quietly: the job succeeds, the dashboard refreshes, and the number is wrong. Six sessions around one question: for each bug your pipeline could ship, which test would fail, and what does that test cost to run?

The six sessions 🎯 · from a bug list to a test plan someone keeps running

The running case is Wrenfold (constructed), a city bike-share operator whose pipeline turns raw trips into cleaned trips, then station-hour counts, then a demand forecast that decides where to move bikes. Wrenfold is invented; the trips it processes are real: 13,810 trips from HSL's Helsinki city bike data for May 2021. Each session adds one piece to Wrenfold's test plan.

🔕 Session 1 · foundations

What test would fail if the code were wrong?

Silent failure, the twelve bug classes data and ML code ship (nulls, fan-out, units, timezones, leakage, skew and more), and a test pyramid redrawn for data. Build-along: break a Wrenfold transform and watch the existing test stay green.

▶ Start here 🧩 Session 2 · foundations

Unit tests for transforms: pytest, fixtures, small fake data

Arrange, act, assert; fixtures and parametrize; why a pure function is cheap to test and a function that reads a file is not. Build-along: four tests for Wrenfold's trip cleaner.

tests for the code 📏 Session 3 · core

Data checks: schema, ranges, uniqueness, distributions

Expectation suites, dataframe schemas and dbt data tests as one category; static checks against distribution checks, and what a false alarm costs. Build-along: a check suite for cleaned trips.

tests for the data 🧫 Session 4 · bench night

The bench: bug catcher

A real pipeline on real trips, twelve bug injectors and seventeen tests, all running in your browser. Read the catch matrix, tighten the thresholds and count the false alarms, then find the cheapest set that catches every bug.

★ the bench 🧭 Session 5 · stretch

Model behaviour tests: invariance, directional, minimum functionality

CheckList's three test types applied to a demand forecast, the ML Test Score rubric, and the open argument about how much ML testing a model needs before it earns its keep. Build-along: three behaviour tests on Wrenfold's model.

tests for the model 🗓️ Session 6 · capstone

A test strategy someone keeps running

What runs on every commit, nightly and at release; a runtime budget; flaky data tests; who owns a failing check. Capstone: Wrenfold's whole test plan, scored on the bench.
